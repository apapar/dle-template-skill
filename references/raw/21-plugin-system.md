# Plugin System

*DLE documentation topic #21*

This plugin system allows you to modify any functionality of the script as you wish. Installing plugins on the website and updating plugins is done with one click directly in the DataLife Engine control panel. If a plugin is developed for the new system, users no longer have to read installation instructions, edit script files manually, and so on. They simply upload the plugin in the admin panel and that is all.

The plugin system is built using virtual file system technology. In the plugin, you describe which file needs which actions to be performed, and based on this information DataLife Engine creates virtual copies of these files with all required changes and modifications, then works with these virtual copies without affecting the original files. At the same time, you can describe changes in almost all files except for a number of basic ones, for example root files, but they do not carry any functionality other than including other files. The functionality of files responsible for AJAX functions can also be changed; for this purpose they were completely rewritten to work through a controller. What advantages does this provide? First, the original files always remain unchanged, so plugins can easily be modified, removed, updated, and so on. Second, this system creates the minimum possible load on websites overall, because virtual copies of files are created only once, at the moment of plugin installation or update. After that, DataLife Engine works with these modified files as with ordinary native files, and there are no memory costs for hook points, storing, and controlling information about where and what functionality must be changed, and so on. Server load increases only by the load introduced by the plugin itself, while the plugin management system does not create any additional overhead. Third, there are no problems with updating the script itself: the script can be updated to new versions, while your plugins are automatically applied to the new versions. Different plugins can also modify the same file without causing conflicts, provided that different plugins do not perform directly opposite actions.

So, in the plugin management module itself, you can either create a plugin directly in the control panel or upload a ready-made plugin. Let us consider adding a new plugin directly in the control panel:

On the first tab, you define the general data of the plugin: its name and short description. For easier distinction from other plugins, you can specify an icon that it will use in the plugin list. You also specify the version of the plugin itself and the version of DataLife Engine with which it is compatible.

On the next tab, you define the actions that need to be performed on files. You can add one or several files for which actions must be performed, and for each file assign one or several actions that need to be applied. In files, you can perform the following actions:

  1. Find and replace specific code.
  2. Find and add required code above it.
  3. Find and add code below it.
  4. Completely replace the file content with your own.
  5. Create a new virtual file that does not exist in the original DLE.

You can also add or remove files at any time, change or delete actions for files. For convenience of reading and editing, all code is highlighted and fields can expand dynamically.

As a result, the situation where you previously edited script files manually, stored the changes somewhere in a notebook, and every time the script was updated you re-applied those changes to the files, is completely a thing of the past. You can create your own personal plugin directly in the admin panel, describe the changes you need in the script only once, and when the script is updated to a new version, you will no longer have to worry about it: your changes will be applied to new versions automatically.

On the next tab, you can add the necessary actions in the MySQL database that the plugin must perform in certain situations. You can specify a list of MySQL queries that must be executed when the plugin is installed, updated, disabled, enabled, or deleted. At the same time, for each action you can define either one query or a list of several database queries.

For an existing plugin, you can perform the following actions: you can disable it, in which case it remains on the website but is completely ignored by the script and all its file actions are suspended. You can update it to a newer version if one exists. You can download the plugin to your computer to install it on another website. The file itself is downloaded in XML format, and this XML contains a description of all actions. In essence, a plugin is an XML file that can be installed on the website through the admin panel.

Let us consider uploading a ready-made plugin to the website. You can upload and install a ready-made plugin on your website. By clicking the corresponding button, you can upload either an XML file with a plugin or a ZIP archive with a plugin. This makes it possible to create very complex plugins that contain a large number of other additional files, both graphic files and PHP files. For example, instead of describing all actions directly inside the plugin itself, you can create additional files and pack them into the archive, placing them in new locations. It is important to know that the archive may contain only those PHP files that are not part of the distribution, but only your own additional files. If the archive contains files that belong to the distribution, such an upload will be blocked. Modifications to standard files must be described in the plugin itself. The XML plugin file itself must be located in the root of your archive.

If you upload an archive with a plugin and DataLife Engine does not have write permissions for the files contained in your archive, it will automatically request FTP access in order to upload your archive. If access is not required, everything will be copied automatically without it. These credentials are not stored anywhere and are deleted automatically after they are no longer needed.

The plugin management system also has a built-in plugin error logging system. If any file action cannot be performed or any errors occur, you can easily see and fix them. For example, this is extremely convenient if your plugin is incompatible with the next DLE version: you will notice it quickly and can adapt the plugin easily.

Plugins can use the `[lang=X]` text `[/lang]` tags in the plugin name, plugin description, and plugin notes. These tags output text depending on the language used by the user in the admin panel, where X is the ISO language code from the language pack. This allows you to display names and notes in different languages. For example, the tag `[lang=ru]`Russian text`[/lang]` will output this text if the user uses the Russian language, while the tag `[lang=en]` English Text `[/lang]` will output the English text if the user uses the English language.
